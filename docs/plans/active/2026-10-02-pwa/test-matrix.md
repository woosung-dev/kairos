> `public-only` 의 browser 그룹은 CI 에서 한 번도 돈 적 없는 형태다 (`security-headers.spec.ts:1-4` — CI chromium `ERR_NAME_NOT_RESOLVED` 회피 이력). 판정 절차: draft PR CI spike → 통과하면 `✅` 승격, 실패하면 CI 에선 `test.skip(!!process.env.CI, '<사유>')` + 로컬 게이트 증거로 대체 (pwa.md R-1).
> 설치 가능성은 CI 에서 판정하지 않는다 — 헤드리스 Chromium 147 의 `Page.getInstallabilityErrors` 는 음성 대조군에도 `[]` 를 돌려준다 (2026-10-02 실측, pwa.md C-8).
> **허용 콘솔 메시지** (browser 그룹·chromium 공통):
> - `console.error` = **0건**. SCR-001 이 200 이라 문서 자체의 로드 실패 error 가 없다 (pwa.md C-24). ★headed Chrome 은 아이콘 선언이 없으면 `/favicon.ico` 를 요청해 오프라인 error 1건을 남긴다 — Playwright 번들 chromium-headless-shell 147 에서만 favicon 요청이 없어 안 보이므로 (Chrome 154 headless 는 요청한다, EVAL-IMPL-2) SCR-001 의 `data:` 아이콘 선언(T-PWA-12 vitest)으로 막는다 (pwa.md §4.4, EVAL-IMPL-1 D2). **유일한 예외**: T-PWA-23 (오프라인 `<Link>` 측정) 에서만 ① Next 의 "Failed to fetch RSC payload" ② `Failed to load resource` 중 **`message.location().url` 이 `/sign-up?_rsc=` 를 포함**하는 것 (테스트가 abort 한 RSC fetch — 텍스트만으로는 허용하지 않는다).
> - `console.warn` 허용 2종 — registrar 의 등록 실패 1줄 · `serviceWorkers: "block"` 컨텍스트의 Playwright 주입 문구 `Service Worker registration blocked by Playwright` 1줄 (pwa.md C-26). 그 외 warning 은 원문을 evidence 에 기록.
> **오프라인 재현 규칙** (pwa.md C-22): **Playwright 번들 Chromium 147 한정** — `context.setOffline(true)` 는 SW 의 **첫** 내비게이션 fetch 만 실패시킨다 → 새 컨텍스트의 첫 reload 1회만 판정에 쓴다. Chrome 154 는 오프라인이 유지된다 (EVAL-IMPL-2) — 그래서 판정이 이 누수 유무에 기대면 안 된다 (③ 은 setOffline 을 쓰지 않는다). 실패를 유지해야 하는 단계는 `context.route(…, r => r.abort("internetdisconnected"))` 를 쓴다 (SW fetch 에도 적용, 3/3).
