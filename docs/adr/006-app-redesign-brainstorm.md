# ADR-006: 서비스 전면 UI/UX 개편 — 브레인스토밍 결과

**날짜:** 2026-04-04
**상태:** 확정
**결정자:** woo sung
**검증 방법:** 브레인스토밍 → 생각 트리 → 소크라테스식 논증 → Sequential Thinking

---

## 배경

랜딩 리디자인(ADR-005) 완료 후, 실제 서비스(대시보드/앱)의 UI/UX가 제품 비전("팀의 세컨드 브레인") 대비 부족하다고 판단. 백엔드 API 미연동 상태(Empty State)이므로 구조 변경 적기. 기능 구조, 화면 흐름, 네비게이션을 근본적으로 재설계.

---

## 확정된 의사결정 (11개)

### 1. 홈 화면 — 조건부 홈 (B+A 하이브리드)
- MVP: Inbox/Today 중심
- 신규 → 온보딩, 초기 → Inbox+마감액션, 활성 → 상단 RAG 검색바 + Today 피드
- RAG 검색: Cmd+K 또는 상단 검색바로 항상 접근 가능

### 2. NotebookLM 기능 수용
- ✅ 출처(Sources) 패널: 필수
- ✅ 인라인 출처 채팅 ([1][2][3] → 원문 하이라이트): 필수
- ❌ 스튜디오: 내부 미구현 → 내보내기/가져오기 허브로 대체

### 3. 레이아웃 — C|D 절충안 (8.5/10)
- 좌측: 프로젝트+소스 트리 + Inbox/오늘 할일 (C의 장점)
- 중앙: 넓은 메인 영역 (D의 장점)
- RAG: 상단 검색바 항상 노출 + Cmd+K 슬라이드 오버레이
- 기존 3-Panel RAG 상시 320px 패널 제거

### 4. RAG 인터랙션
- 인라인 [1][2][3] 색상 구분 (teal/purple/amber)
- [1] 클릭 → 메인에 소스 뷰어 열림 + 원문 하이라이트 + 자동 스크롤
- 소스 범위: 3단계 스코프 (전체 / 현재 프로젝트 / 선택한 소스)
- 응답 하단 액션: 복사 / 노트로 저장 / 내보내기

### 5. 내보내기/가져오기 허브 (Studio 대체)
- 내보내기: Markdown / 프롬프트 복사 / JSON / PDF
- 가져오기: 파일 업로드 / 텍스트 붙여넣기 / URL
- 플라이휠: Kairos 정리 → 외부 생성 → Kairos 저장 → RAG 검색

### 6. 프로젝트 상세 — 대시보드형 (7.6/10)
- Sequential Thinking 검증: A(탭) 6.8 / B(피드) 6.4 / C(대시보드) 7.6
- 소크라테스 결론: "A의 요약 탭을 풍부하게 만들면 C가 된다"
- 최상단: L3 프로액티브 인사이트 → 2컬럼 (회의/노트 + 액션/내보내기)
- 콘텐츠 3개 미만 → 온보딩 뷰 전환

### 7. Inbox — 스마트 일괄 처리 + 되돌리기
- 2그룹: ⚠️ 확인 필요 (신뢰도 < 임계값) / ✅ AI 자동 처리 (≥ 임계값)
- 신뢰도 임계값 사용자 조절 (기본 90%)
- 자동 확정도 ✏️수정 / ↩되돌리기 가능

### 8. 회의 상세 — 요약 중심 + 인라인 출처 + 3뷰 전환
- 요약 (기본): L1+L2 + [1][2][3] → 클릭 시 스니펫 펼침
- 트랜스크립트: 전체 원문 + 출처 마커 하이라이트 + 검색
- 액션: 할 일 목록 + 출처 연결

### 9. 노트/소스 입력 — 빠른 메모 + 외부 가져오기
- 이전 결정(Tiptap 블록 에디터) → 변경. 소크라테스 재검토 결과.
- 핵심: "입구는 여러 개, 파이프라인은 하나"
- 빠른 메모: 마크다운 텍스트 (Tiptap 불필요)
- 외부: 파일 업로드 / 텍스트 붙여넣기 / URL
- 에디터 품질이 아니라 파이프라인이 가치

### 10. 온보딩 — 템플릿 프로젝트 + 첫 액션 유도
- 가입 즉시 "🎓 Kairos 시작 가이드" 자동 생성
- 샘플 회의 요약 + 액션 + RAG 데모 포함
- 즉시 RAG 체험 가능 + "첫 회의 녹음하기" CTA

### 11. 모바일 — BottomNav 미세 조정
- [홈(Today)] [프로젝트] [+ 추가] [Inbox] [검색]
- 홈: RAG → Today 피드, + 추가: 업로드 → 회의/메모/파일 통합
