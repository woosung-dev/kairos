## 1. 첫인상 (5초)

**5초 룰: PASS**

**1인칭 인상 (박지원, PM):**
> "AI가 정리합니다. 당신은 결정만 하세요." — 한 문장으로 무엇을 해주는지 들어왔다. "Capture → Organize → Distill → Express" 라벨로 워크플로우 단계도 즉시 보임. CTA 두 개("무료로 시작하기" / "어떻게 작동하나요?")가 명확하게 분리돼 있다. "설정 5분 · 14일 무료 · 신용카드 불필요" 마이크로카피가 가입 마찰에 대한 1차 안심을 준다.

**분석가 시각:**
- Above-the-fold 헤드라인 = 가치명제 직진형. PM 관점에서 이해도 만점.
- 서브카피("팀의 대화, 노트, 자료가 CODE 파이프라인을 거치면…")가 약간 길고 'CODE 파이프라인' 같은 자체 용어를 그대로 노출 — 외부 PM은 "CODE가 뭐야"부터 의심. 5초 룰은 헤드라인+CTA로 통과하지만, 30초 룰에서 CODE 학습 비용이 발생.
- 우측 카드 모킹("⌘K — 정리된 지식이 이렇게 활용됩니다")이 실제 결과물 형태(인사이트/교훈/회의)를 미리 보여줘 신뢰도를 끌어올림. Granola/Otter와 차별 포인트.

**감점 1: 신뢰 신호 부족** — 로고(고객사), 사용자 수, "Y Combinator W25" 같은 사회적 증거가 0개. PM은 첫인상에서 "누가 쓰고 있나?"를 본능적으로 찾는다.

## 2. 가치 이해 (30초 → 1분)

**30초 룰: PASS (조건부)**

**30초 스캔으로 알게 된 것:**
1. CODE 파이프라인 = Capture(녹음/노트/문서) → Organize(자동 태깅) → Distill(L1~L4 증류) → Express(RAG Q&A)
2. "이 문제들, 익숙하지 않으세요?" 섹션이 WITHOUT/WITH 대조 — 회의록 분실, 결정 맥락 망각, 신입 온보딩 지연 등 PM의 페인을 정확히 짚음
3. "팀이 진화하는 세 단계" (W1 / M1 / Q1) — 시간축 약속. "신입 온보딩 절반으로", "조직이 같은 실수를 반복하지 않는다"

**1분 룰: PASS**

가치 명제가 일관되게 "AI 자동화 + 누적 인사이트"로 수렴. 통계 카드(95% / 12x / 24h)가 마지막 push 역할.

**분석가 지적:**
- L1~L4 라벨이 4단계 카드에 그냥 노출됨. PM 입장에서 "L1=콘텐츠 요약, L4=조직 인사이트" 만으로는 차이가 직관적이지 않음. "L4가 정확히 무엇인가" 예시 카드가 있었다면 30초 룰에서 만점.
- 통계 95% / 12x / 24h 출처 미표기 — 자체 추정인지, 베타 사용자 측정인지 모호. PM은 출처 없는 숫자를 의심한다.
- 가격 페이지 링크("요금" → #cta)가 가격이 아닌 "무료 체험 시작" CTA 섹션으로 점프. **가격 정보 0개** — 도입 결정 단계에서 큰 문제.

## 4. TTFV 측정값

**TTFV: 측정 불가 (Critical Blocker — 5분 후에도 가치 도달 0)**

**상세 타임라인:**
- T+0초: 로그인 성공
- T+1초: `/dashboard` 진입
- T+1~10초: "로딩 중..." 텍스트만 표시. 6초+ 대기 후에도 변화 없음 → 무한 로딩 의심
- T+15초: 사이드바의 "Inbox 3" 배지를 보고 → `/inbox` 클릭
- T+16초: Inbox 페이지 = "처리할 항목이 없습니다" (사이드바 배지 3과 모순)
- T+25초: "오늘 할 일" 메뉴 클릭 → **404 Page Not Found** 페이지로 이동 (네비 링크가 죽음)

**도달한 가치 = 0**. PM은 "데모 화면을 봤지만 내 데이터로 무엇을 할 수 있을지 보여주는 게 하나도 없다"고 결론. 빈 워크스페이스에 대한 onboarding이 전무.

**비교:** Otter.ai 가입 직후 → 샘플 회의 + "녹음 시작" 버튼 강조. Notion AI → 템플릿 갤러리. Granola → 캘린더 연결 안내.
**Kairos:** 빈 화면 + 무한 로딩 + 깨진 메뉴.

## 5. 핵심 가치 검증

**RAG 검증: PASS (제품의 진짜 hero feature)**

대시보드의 추천 질문 버튼을 처음 클릭했을 때는 아무 일도 안 일어났지만 (버그), 메인 콘텐츠의 "검색하거나 질문 입력..." 입력 박스를 직접 클릭하면 Command Palette가 떴다. 거기서 "?" 접두사로 질문을 입력하니 **실제로 답변이 나왔다**.

**테스트 결과:**

| 질문 | 결과 |
|------|------|
| "이번 주 회의 내용 요약해줘" (자동 발화) | "이번 주 E2E 테스트 회의(2026-05-13)의 주요 내용은 다음과 같습니다. * 프로젝트 현황 리뷰 * 다음 스프린트 계획" — 소스 10건 |
| "이번 주 회의에서 결정된 사항은?" | "제공된 소스에서… 결정된 사항에 대한 정보를 찾지 못했습니다. 소스에는 회의의 주요 안건(…)만 언급되어 있으며, 해당 안건에 대한 결정 사항은 명시되어 있지 않습니다." — 소스 10건 |

**PM 1인칭 인상:**
> 두 번째 답변이 인상적이었다. "결정 사항은 명시되어 있지 않습니다"라고 **솔직하게 답하면서** 무엇이 있고 없는지 구체적으로 명시했다. Otter.ai의 요약은 종종 "있어 보이는" 환각을 만든다. Kairos는 RAG citation을 신뢰 신호로 활용하는 설계가 명확하다. 소스 10건이 함께 보이는 것 = 검증 가능성.

**대시보드 다른 컴포넌트:**
- "오늘의 Kairos" 위젯: Inbox 미분류 5건 / 진행 중 액션 4건 / 최근 활동 5건 — 5분 만에 보면 좋다. **단, 사이드바 "Inbox 3"과 대시보드 "Inbox 미분류 5건"이 불일치** — 데이터 sync 결함.
- 추천 질문 버튼 클릭은 동작 안 함 → 입력박스 직접 클릭이 필요 (UX flow 단절).

**Inbox 페이지 결함:** 사이드바 배지 "Inbox 3"인데 페이지 진입 시 "처리할 항목이 없습니다" — 사용자에게 모순된 정보 노출.

## 6. 도입 결정: **Maybe (조건부)**

**도입 결정: Maybe**

**Yes로 기우는 이유:**
- RAG citation 품질 자체는 경쟁사 대비 분명한 차별점 (환각 억제 + 출처 명시).
- CODE 파이프라인 약속 ("L1~L4")이 다른 도구의 단순 요약과 다른 깊이를 약속.
- "팀이 진화하는 W1/M1/Q1" 시간축 narrative가 PM의 long-term ROI 사고와 부합.

**No로 기우는 이유 (모두 즉시 fixable):**
1. **"Development mode" 배지가 가입 화면에 노출** — 검증 PM이 보면 즉시 이탈. 프로덕션 Clerk 키 미적용 의심.
2. **"오늘 할 일" 네비 링크가 404** — 사이드바 메뉴가 죽어 있음. "QA 안 한 제품" 신호.
3. **사이드바 vs 대시보드 카운트 불일치 (Inbox 3 vs 5)** — 데이터 신뢰성 의심.
4. **추천 질문 버튼 클릭 무반응** — Hero 경로의 dead button.
5. **가격 정보 0개** — B2B 도입 검토 PM은 가격 없이 다음 단계로 갈 수 없음.
6. **Clerk 위젯 영어 표시** — 한국어 랜딩에서 갑작스러운 영어 전환.
7. **신뢰 신호 (고객 로고/사용 사례) 0개** — "이게 진짜 운영되는 제품인가?" 의심.

**결정 paraphrase:** "기술 코어(RAG, AI 파이프라인)는 매력적인데, 가입 첫인상부터 깨진 링크 + Dev 배지를 보고 나면 '아직 우리 팀이 쓸 수준은 아닌데 6개월 후 다시 보자'고 북마크. 도입 PoC는 보류."

## 8. 경쟁 차별성 인식

**Granola / Otter.ai / Notion AI / Fireflies와 어떻게 다른가? — PM 시각**

| 차별점 | Kairos가 약속하는 것 | 검증 가능성 |
|--------|---------------------|------------|
| **L4 조직 인사이트** | 단일 회의 요약을 넘어 "조직이 같은 실수를 반복하지 않는다" 라는 누적 메타 인사이트 | 랜딩에서 약속 명확, 단 단일 사용자 화면에선 검증 불가 (팀 규모 + 시간 누적 필요) |
| **RAG citation** | 답변 + 소스 10건 노출, 환각 억제 | **실제 검증됨 (검색 결과 솔직성: 결정사항 없으면 "없다"고 답)** |
| **CODE 파이프라인 자동화** | Capture → Organize → Distill → Express 단계별 자동화 | Inbox 자동 분류, Project 자동 연결 — UI에 흔적은 있으나 사용자 체험은 빈 워크스페이스라 검증 불가 |
| **프로액티브 인사이트** | "현재 프로젝트에서 유사 패턴 감지" (랜딩 모킹) | 모킹뿐, 실제 동작 확인 불가 |

**경쟁 차별성 인식: 7/10**

차별점 자체는 명확. **단 4개 중 1개(RAG citation)만 5분 안에 검증 가능**. 나머지는 시간이 누적돼야 가치가 드러나는 구조라 PM은 PoC를 더 길게 운영해야 결론 가능. "다른 도구와 다른가?"는 명확하지만 "지금 당장 우리에게 더 좋은가?"는 모호.

**놓친 비교 카피:** 랜딩에 "vs Otter" / "vs Granola" 비교표나 "왜 Notion AI로 부족한가" 섹션이 없음. 검토 PM은 본능적으로 이런 섹션을 찾는다.

- 블로그 / 변경 로그 / 공개 로드맵
- 통계(95%/12x/24h)의 출처 표기

## 10. 개선 우선순위 (PM 시각)

**P0 (가입 마찰을 막는 출혈 — 1주 내 fix):**
1. Clerk 프로덕션 키 적용, "Development mode" 배지 제거
2. Clerk 위젯 한국어 로컬라이즈 (Clerk localization)
3. 사이드바 "오늘 할 일" 링크 — 페이지 만들거나 메뉴에서 제거 (404 노출 차단)
4. 사이드바 Inbox 카운트 vs 페이지 데이터 동기화 (badge 신뢰성 회복)
5. ToS/Privacy 링크를 가입 화면 하단에 명시

**P1 (도입 결정 차단 요소 — 2~4주 내):**
6. 가격 페이지 추가 (Free / Team / Enterprise tier 명시)
