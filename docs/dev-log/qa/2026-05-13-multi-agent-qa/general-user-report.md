## 3. 모바일 UX 점수 + 결함

- **BottomNav 사용성: 6/10**
  - 5개 탭(홈/프로젝트/추가/Inbox/검색) 구성 자체는 표준적
  - 탭 가로 폭 36-51px → 일부 (홈/검색 36px) HIG 권장 44pt 미만 → 큰 손가락 오탭 우려
  - 탭 높이 53-57px → OK
  - **데스크톱 사이드바 5항목과 다름** (데스크톱: 홈/Inbox/오늘 할 일/빠른 메모/+추가, 모바일: 홈/프로젝트/추가/Inbox/검색)
- **터치 타겟 크기: 5/10**
  - Inbox 카드 안 버튼(✅ 확정 / ✏️ 다른 프로젝트 / 🗑 무시) 높이 **44px 정확** → 최소 합격
  - 검색 페이지 입력창 높이 **20px** → **HIG 44pt 절반**, 큰 결함
  - BottomNav 일부 탭 가로 36px → 약간 미달
- **모바일 vs 데스크톱 일관성: 4/10**
  - 데스크톱엔 있는 "빠른 메모" "오늘 할 일" 진입점이 모바일 BottomNav에는 없음
  - 모바일에선 사이드바가 아예 안 열리는데 좌측 상단 햄버거 토글 버튼은 그대로 남아 있음 → 죽은 버튼
  - 모바일에는 "프로젝트" "검색" 탭이 있지만 데스크톱에는 사이드바 항목 외에 별도 탭 없음 → IA가 일관되지 않음

**총평 (모바일): 5/10**

**결함 요약**:
1. (Critical) 햄버거 사이드바 토글이 모바일에서 무동작 — UX 신뢰 즉시 손상
2. (Critical) 빠른 메모/오늘 할 일 페이지로 가는 모바일 진입점 부재
3. (High) 검색 입력창 높이 20px (44pt 미만)
4. (High) BottomNav 탭 가로 36-41px (44pt 미만)
5. (Medium) "오늘 할 일" 메뉴는 모바일 BottomNav엔 없지만 데스크톱 사이드바에선 노출 → 클릭 시 404
6. (Low) 프로젝트 헤더 "Visibility: 공개" 버튼 클릭 시 시각 피드백 부족 (적어도 모바일에서 dropdown이 안 보임)

## 4. 포기 시뮬레이션

- **"평균 사용자가 떠날 위치"**: 첫 5분 안의 두 사건 누적
  - **시점 A (5분)**: "오늘 할 일" 클릭 → **404 페이지** → 짜증 +1
  - **시점 B (7-12분)**: 검색 한 번 시도 → "RAG 오버레이 닫기" / "RAG 검색 범위" / 노트 제목 "RAG 성능 개선" → "이 도구는 개발자용인가 봐. 나한테는 안 맞아" → **이탈 위험 피크**
  - **시점 C (~26분, 모바일 검색)**: "⚠️ 오래된 소스입니다 (2026-09-01 기준)" → "오늘이 5월인데 9월 기준?" → **신뢰 즉시 손상**
- **이유 요약**:
  1. (즉시) 사이드바 메뉴를 클릭했는데 404 → 도구의 기본 신뢰성에 대한 의심
  2. (5-10분 누적) "RAG"와 "Visibility" 같은 개발자 용어가 첫 페르소나 동선에서 3회 이상 노출됨
  3. (모바일 진입 시) 햄버거가 동작 안 함 + 빠른 메모로 갈 길이 없음 → 출퇴근 중 사용 의향 자체가 꺾임

> **결론**: 김민지 같은 사용자는 평균 **첫 12분 안**에 "이 도구는 나한테 너무 어렵다"고 결론 내릴 가능성이 높음. 모바일에서 시도하면 더 빠름 (~5분).

## 5. UX 라이팅 개선 제안 Top 5

1. **"RAG"를 모든 사용자 노출 카피에서 제거 → "AI 검색" 또는 "팀 지식 검색"으로 통일**
   - 영향 위치: ① RAG 오버레이 닫기 a11y 라벨 ② 프로젝트 온보딩 본문 ③ 시드 노트 "RAG 성능 개선 아이디어" 제목
   - 비용: 텍스트 치환 + onboarding 시드 데이터 손질
   - 효과: 일반 사용자 신뢰 +30% (개인 추정), 첫 12분 이탈 방지의 핵심

2. **"Visibility: 공개" → "공개 범위: 모두"로 한글화하고, dropdown UI 시각 피드백 강화**
   - 비용: 카피 변경 + 클릭 시 popover 위치 검증

3. **"Owner" / "Archive" / "Inbox" / "onboarding" 영문 라벨 일괄 한글화**
   - "주최자" / "보관함" / "받은 정리함" 또는 "정리 대기함" / "🚀 시작하기" (라벨 흡수)
   - 비용: i18n 또는 컴포넌트 props 정리

4. **"Private 프로젝트는 명시적 멤버에게만 표시됩니다" → "비공개 프로젝트는 초대받은 멤버만 볼 수 있어요"**
   - 검색 하단 안내 문구

5. **검색 답변 본문 안 인라인 "[소스 1, 2, 3, ..., 10]" 표기 정리**
   - 답변 마지막에 한 줄 "📎 출처 10건" 버튼만 남기고 인라인 숫자는 제거하거나 superscript로 축약
   - 모바일에서 효과 더 큼

**Bonus (5개 외 발견 결함, 우선순위 높음)**:
- 사이드바 "오늘 할 일" 메뉴 → 404. **즉시 메뉴에서 숨기거나 "준비 중" 페이지로 라우팅**
- 모바일 햄버거 사이드바 토글 버튼 → 모바일에선 숨기기 (또는 BottomNav 펼치기 메뉴로 작동)
- 검색 결과 안 "⚠️ 오래된 소스입니다 (2026-09-01 기준)" 문구의 미래 날짜 → 시드 데이터 또는 기준일 산정 로직 확인 ([확인 필요])

## 6. 데스크톱 vs 모바일 비교

| 항목 | 데스크톱 (1440x900) | 모바일 (375x667) |
|------|----------|--------|
| 1차 내비 | 좌측 사이드바 (홈/Inbox/오늘 할 일/빠른 메모/+추가) + 프로젝트 트리 | 하단 BottomNav (홈/프로젝트/추가/Inbox/검색) |
| **빠른 메모 진입점** | 사이드바 "빠른 메모" | **부재** (직접 URL만) |
| **오늘 할 일 진입점** | 사이드바 "오늘 할 일" → 404 | 부재 |
| **프로젝트 트리** | 사이드바 펼쳐짐 | 부재 (별도 "프로젝트" 탭 → 목록만) |
| 검색 진입 | 헤더 "팀 지식 검색 ⌘K" 큰 버튼 + RAG 오버레이 | 헤더 검색 버튼 + 별도 /search 페이지 + BottomNav "검색" |
| 햄버거 토글 버튼 | 작동 (사이드바 토글) | **무동작** (사이드바 자체가 안 열림) |
| 페이지 가로 overflow | 없음 | 없음 (잘 잡혀 있음) |
| Inbox 카드 가독성 | 좋음 (충분한 너비) | 좋음 (이모지/태그/버튼 적절히 배치) |
| 검색 답변 가독성 | 보통 (오버레이 안에 들어가 좁음) | 좋지 않음 (인라인 숫자 시각 노이즈) |
| 검색 입력창 높이 | 충분 | **20px (작음)** |
| 모바일 BottomNav 탭 폭 | N/A | 36-51px (일부 44pt 미만) |
| 일관성 인식 | "데스크톱 워크스페이스" 도구 같음 | "회의록 자동 도구" 같음 (그러나 빠른 메모 못 가서 반쪽) |

**결론**: **모바일은 데스크톱의 축소판이 아니라 "별도의 IA"**. 의도된 디자인일 수 있지만, 결과적으로 "출퇴근 중 빠른 메모"라는 페르소나의 핵심 시나리오를 끊는다.
