## 2. BL-003: `_enrich_context` N+1 → 배치 쿼리

### 현재 문제

```python
# rag/service.py:175-186
async def _enrich_context(self, results: list[dict]) -> list[dict]:
    for r in results:
        parent_id = r.get("parent_chunk_id")
        if parent_id:
            parent = await self.embedding_repo.find_chunk_by_id(parent_id)  # N+1
```

결과 수(최대 10)만큼 DB 쿼리 발생.

### 변경 사항

**`backend/src/embeddings/repository.py` — 신규 메서드 추가**

```python
async def find_chunks_by_ids(
    self, ids: list[UUID]
) -> dict[UUID, EmbeddingChunk]:
    """여러 청크를 배치로 조회한다. 결과 없으면 빈 dict 반환."""
    if not ids:
        return {}
    result = await self.session.execute(
        select(EmbeddingChunk).where(EmbeddingChunk.id.in_(ids))
    )
    return {c.id: c for c in result.scalars().all()}
```

**`backend/src/rag/service.py` — `_enrich_context` 배치 호출로 변경**

```python
async def _enrich_context(self, results: list[dict]) -> list[dict]:
    """Level 2 검색 결과에 parent Level 1 컨텍스트 추가. 배치 쿼리 1회."""
    parent_ids = [
        UUID(r["parent_chunk_id"])
        for r in results if r.get("parent_chunk_id")
    ]
    parents = await self.embedding_repo.find_chunks_by_ids(parent_ids)
    enriched = []
    for r in results:
        parent_text = ""
        pid_str = r.get("parent_chunk_id")
        if pid_str:
            parent = parents.get(UUID(pid_str))
            if parent:
                parent_text = parent.chunk_text
        enriched.append({**r, "parent_text": parent_text})
    return enriched
```

### 영향 범위

- `backend/src/embeddings/repository.py` — 메서드 1개 추가 (기존 메서드 유지)
- `backend/src/rag/service.py` — `_enrich_context` 내부 변경 (인터페이스 불변)
- 기존 caller(`rag/service.py:ask`) 변경 없음

### 변경 사항

**`backend/src/common/prompts.py` 하단에 추가**

```python
# ── LLM 응답 계약 스키마 ──
# 프롬프트 출력 스키마와 동기화 유지. 키 변경 시 프롬프트 텍스트와 함께 수정.
from pydantic import BaseModel

class MeetingSummaryResult(BaseModel):
    summary: str
    key_decisions: list[str] = []
    risks_and_issues: list[str] = []
    participants: list[str] = []
    topics: list[str] = []
    next_meeting_agenda: list[str] = []

class MeetingActionsResult(BaseModel):
    actionItems: list[dict] = []
    suggestedProject: dict = {}
    suggestedTags: list[str] = []
```

**`backend/src/services/ai_processing.py` — 검증 추가**

```python
from src.common.prompts import (

    MeetingSummaryResult,

async def summarize(self, transcript: str) -> dict:
```

`stream_rag_answer()`는 JSON 응답이 아닌 스트리밍 텍스트이므로 변경 없음.

### 영향 범위

- `backend/src/common/prompts.py` — Pydantic 모델 2개 추가 (기존 코드 수정 없음)
- `backend/src/services/ai_processing.py` — import 1줄, 검증 2줄 추가
- `pipeline_service.py` 등 callers 변경 없음 (반환 타입 `dict` 유지)

### 에러 처리

`model_validate()` 실패 시 `pydantic.ValidationError` 발생 (`Exception` 서브클래스). 기존 pipeline이 이미 `except Exception → status=failed` 패턴으로 처리하므로 별도 핸들링 불필요. Gemini 응답 파싱 실패(`ValueError`)와 동일 경로로 처리됨.
